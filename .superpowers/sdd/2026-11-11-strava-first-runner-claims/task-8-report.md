# Task 8 report

Implemented the worker-backed version 1 snapshot build. Selection triggers create the building row and one project job atomically; explicit confirmation uses the new service-only RPC. Project jobs validate the selected normalized detail, build a privacy-allowlisted projection, and complete through lease, generation, attachment, selection, and build fences. Locked runner/category/event rows are compared with the projected context before publication; a mismatch retries the build. Webhooks rebuild the existing version, including unchanged detail. Failures use the existing bounded retry and rate-limit handling and eventually fail the snapshot.

Legacy or incomplete activity cache entries are fetched from Strava with ownership checks, then passed through the existing multi-runner classification/cleanup transaction via a lease-and-build-fenced wrapper. This invalidates an obsolete build and queues a fresh one only for a still-qualifying selection. The normal activity storage allowlist strips location and provider-private fields. Ordinary read routes do not fetch Strava.

Migration `20261112141503_strava_projection_worker.sql` was created with `supabase migration new`; its timestamp was advanced to sort after the existing future-dated migrations. No existing migration was edited. All new RPCs have empty search paths and service-only grants; the renamed old worker commit is not callable by service_role. No hosted database migration was applied.

## Review fixes for round 4

### Task 15 rollout procedure and limits

The immutable round-3 migration `20261112145626_strava_projection_review_round3.sql` still installs triggers on both tables in one transaction. The migration can acquire its job-table DDL lock and then wait for an old transaction's connection-table lock, while the old transaction waits to update the job table. Round 4 removes the second trigger after installation, so the one-time round-3 deadlock risk remains for databases that have yet to apply it. The connection-trigger drop and subsequent repair must commit separately. [PostgreSQL explicit locking](https://www.postgresql.org/docs/current/explicit-locking.html)

For Task 15, rehearse the ordered migrations on a dedicated PostgreSQL instance. Pause all worker invocations, gate other Strava writers during the trigger migration window, and wait for old requests to drain. The current handler budget is 60 seconds and project leases last two minutes. Use the live activity and lock views to confirm relevant transactions have ended, allowing for the lease window when checking for stranded jobs. Apply each migration in its own transaction with a bounded lock timeout and a rehearsed statement timeout. On a lock timeout or deadlock, verify rollback and migration history, identify the remaining blocker, and retry only after it drains. Verify the job trigger is present, the connection trigger is absent, and the repair has run before resuming workers on the new application version. [Supabase database migrations](https://supabase.com/docs/guides/deployment/database-migrations)
